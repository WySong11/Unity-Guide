Unity Addressables Package
쉽고 자세한 설명

Addressables는 “에셋을 주소로 부르고, 필요한 순간에 로드하며, 필요 없을 때 해제하는” Unity의 런타임 에셋 관리 시스템입니다. 특히 모바일 게임처럼 앱 용량을 줄이고, 스킨·스테이지·사운드·DLC 같은 추가 콘텐츠를 서버에서 내려받고 싶을 때 매우 유용합니다.

한 문장으로 이해하기

기존 방식은 “씬이나 프리팹이 에셋을 직접 들고 있는 구조”에 가깝고, Addressables는 “주소표/catalog를 보고 에셋 위치를 찾아 로드하는 구조”입니다.

앱 용량 절감 서버 다운로드 AssetBundle 자동 관리 메모리 Release 관리

먼저 기억할 핵심

  • Address는 “에셋 이름표”입니다.
  • Catalog는 “주소 → 실제 위치” 지도입니다.
  • Group은 “같이 빌드/로드할 묶음”입니다.
  • Remote Group은 서버/CDN에서 받을 수 있습니다.
  • Load한 것은 나중에 Release해야 합니다.

1. Addressables가 뭔가요?

Unity 프로젝트 안의 Prefab, Sprite, Texture, AudioClip, Material, Scene 같은 에셋을 주소(Address)로 관리하고, 런타임에 필요할 때 비동기 로드할 수 있게 해주는 패키지입니다.

그림 1. Addressables는 직접 참조 대신 “주소 → Catalog → AssetBundle → Asset” 흐름으로 에셋을 찾습니다.

핵심 용어

용어쉬운 설명예시
Address에셋을 부르는 문자열 이름입니다. 코드에서는 이 주소로 로드합니다."ui/icon_save", "enemy/slime"
Group에셋을 묶는 단위입니다. Group 설정에 따라 Local/Remote, 번들 묶는 방식, 압축 방식 등이 정해집니다.Local_Essential, Remote_Stage_01

중요: Addressables는 “에셋을 안 쓰면 자동으로 다 해결되는 마법”이 아닙니다. 어떤 에셋을 Local에 넣고, 어떤 에셋을 Remote에 둘지, Group을 어떻게 나눌지, 언제 Load/Release할지 직접 설계해야 합니다.

2. Addressables 로드 흐름 그림

런타임에서 Addressables.LoadAssetAsync 또는 AssetReference.LoadAssetAsync를 호출하면, Addressables는 Catalog를 보고 에셋 위치를 찾습니다. 에셋이 앱 안에 있으면 Local에서 읽고, 서버에 있으면 다운로드 후 캐시에 저장한 뒤 로드합니다.

그림 2. Addressables는 Catalog를 통해 Local, Remote, Cache 중 필요한 경로를 선택합니다.
Local

처음부터 앱 안에 포함

튜토리얼, 공통 UI, 기본 폰트, 첫 로딩에 반드시 필요한 에셋에 적합합니다.

Remote

필요할 때 서버 다운로드

추가 스테이지, 캐릭터 스킨, 이벤트 리소스, 대용량 사운드에 적합합니다.

Cache

한 번 받은 파일 재사용

원격 Bundle은 기기 캐시에 저장될 수 있어서 다음 실행 때 다시 받지 않아도 됩니다.

3. “필수 에셋만 가지고 있다가, 필요할 때 서버에서 다운로드” 구축 순서

가장 흔한 목표는 초기 앱에는 최소한의 에셋만 넣고, 나머지 콘텐츠는 서버/CDN에 올려두었다가 필요한 시점에 다운로드하는 구조입니다.

그림 3. 필수 에셋은 Local Group, 추가 콘텐츠는 Remote Group에 배치합니다.

설정 순서

1

Addressables 설치

Window > Package Manager에서 Addressables를 설치합니다. Unity Editor 버전에 따라 Package Manager에서 보이는 버전이 다를 수 있으므로, 현재 프로젝트 Unity 버전과 호환되는 최신/검증 버전을 선택합니다.

2

Addressables Settings 생성

Window > Asset Management > Addressables > Groups를 열고 Create Addressables Settings를 누릅니다.

3

Local Group과 Remote Group 나누기

처음부터 앱에 포함해야 하는 에셋은 Local, 나중에 서버에서 받을 에셋은 Remote Group으로 나눕니다.

Group 예시넣을 에셋Build & Load Paths
Local_Essential로딩 씬, 기본 UI, 공통 폰트, 기본 아이콘Local
Remote_Stage스테이지별 배경, 타일맵, 몬스터 프리팹Remote
Remote_Skin캐릭터 스킨, 이벤트 아이템 이미지Remote
Remote_AudioBGM, 보이스, 대용량 효과음Remote
4

Remote Catalog 켜기

Window > Asset Management > Addressables > Settings에서 Build Remote Catalog를 활성화합니다. Remote Catalog와 hash 파일도 서버에 업로드되어야 클라이언트가 최신 콘텐츠 위치를 알 수 있습니다.

5

Profiles에서 RemoteLoadPath 설정

Window > Asset Management > Addressables > Profiles에서 서버 URL을 설정합니다.

RemoteBuildPath 예시:
ServerData/[BuildTarget]

RemoteLoadPath 예시:
https://cdn.example.com/mygame/[BuildTarget]

Android, iOS, Windows 등 플랫폼별 AssetBundle이 다르므로 [BuildTarget]을 경로에 포함시키는 방식이 안전합니다.

6

Addressables Content Build 실행

Addressables Groups > Build > New Build > Default Build Script를 실행합니다. 이때 Catalog, hash, AssetBundle 파일들이 생성됩니다.

7

Remote 파일 업로드

ServerData/[BuildTarget]에 생성된 Remote Catalog, hash, Bundle 파일을 서버/CDN의 RemoteLoadPath 위치에 업로드합니다.

8

Player Build

게임을 빌드합니다. 앱에는 Local Group과 기본 Catalog가 들어가고, Remote Group의 실제 대용량 콘텐츠는 서버에서 받을 수 있는 구조가 됩니다.

주의: Remote Addressables로 바꿀 수 있는 것은 주로 에셋입니다. C# 코드, 스크립트 로직, 빌드에 포함되어야 하는 네이티브 플러그인 같은 것은 일반적으로 앱 업데이트가 필요합니다.

4. 자주 쓰는 코드 예제

Addressables API는 대부분 비동기입니다. 로딩 중 UI를 보여주거나, 다운로드 진행률을 표시하기 좋습니다.

4-1. Address 문자열로 Prefab 로드 후 생성

가장 기본적인 방식입니다. 주소 문자열로 Prefab을 로드한 뒤 Instantiate합니다.

using System.Collections;
using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

public class AddressLoadExample : MonoBehaviour
{
    [SerializeField] private string m_prefabAddress = "enemy/slime";

    private AsyncOperationHandle<GameObject> m_loadHandle;
    private GameObject m_instance;

    private IEnumerator Start()
    {
        // 1. 주소로 에셋 로드 요청
        m_loadHandle = Addressables.LoadAssetAsync<GameObject>(m_prefabAddress);

        // 2. 로드가 끝날 때까지 기다림
        yield return m_loadHandle;

        // 3. 성공하면 실제 게임 오브젝트 생성
        if (m_loadHandle.Status == AsyncOperationStatus.Succeeded)
        {
            GameObject prefab = m_loadHandle.Result;
            m_instance = Instantiate(prefab, Vector3.zero, Quaternion.identity);
        }
        else
        {
            Debug.LogError($"Addressables Load Failed: {m_prefabAddress}");
        }
    }

    private void OnDestroy()
    {
        // 직접 Instantiate한 오브젝트는 직접 Destroy
        if (m_instance != null)
            Destroy(m_instance);

        // LoadAssetAsync로 잡은 핸들은 Release
        if (m_loadHandle.IsValid())
            Addressables.Release(m_loadHandle);
    }
}
입문자 포인트: LoadAssetAsync는 “원본 Prefab 에셋을 메모리에 올리는 것”이고, Instantiate는 “그 Prefab을 씬에 복사해서 배치하는 것”입니다.

4-2. AssetReferenceGameObject로 Prefab 생성

Inspector에서 Addressable Prefab을 직접 끌어다 넣고 싶다면 이 방식이 편합니다.

using System.Collections;
using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

public class AssetReferenceInstantiateExample : MonoBehaviour
{
    [SerializeField] private AssetReferenceGameObject m_enemyPrefabRef;

    private AsyncOperationHandle<GameObject> m_instanceHandle;

    private IEnumerator Start()
    {
        // Addressables가 로드와 Instantiate를 함께 처리
        m_instanceHandle = m_enemyPrefabRef.InstantiateAsync(Vector3.zero, Quaternion.identity);
        yield return m_instanceHandle;

        if (m_instanceHandle.Status == AsyncOperationStatus.Succeeded)
        {
            Debug.Log("Enemy Created");
        }
    }

    private void OnDestroy()
    {
        // InstantiateAsync로 만든 오브젝트는 ReleaseInstance로 해제
        if (m_instanceHandle.IsValid())
            Addressables.ReleaseInstance(m_instanceHandle);
    }
}

4-3. Label 단위로 미리 다운로드

예를 들어 stage_01 라벨이 붙은 에셋들을 스테이지 시작 전에 미리 다운로드할 수 있습니다.

using System.Collections;
using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

public class PreDownloadByLabel : MonoBehaviour
{
    [SerializeField] private string m_label = "stage_01";

    public IEnumerator DownloadStageAssets()
    {
        // 1. 다운로드해야 할 용량 확인
        AsyncOperationHandle<long> sizeHandle = Addressables.GetDownloadSizeAsync(m_label);
        yield return sizeHandle;

        long downloadSize = sizeHandle.Result;
        Addressables.Release(sizeHandle);

        if (downloadSize <= 0)
        {
            Debug.Log("이미 다운로드되어 있거나 Local 콘텐츠입니다.");
            yield break;
        }

        Debug.Log($"다운로드 필요 용량: {downloadSize / 1024f / 1024f:F2} MB");

        // 2. 실제 다운로드
        AsyncOperationHandle downloadHandle = Addressables.DownloadDependenciesAsync(m_label);

        while (!downloadHandle.IsDone)
        {
            float percent = downloadHandle.PercentComplete;
            Debug.Log($"다운로드 진행률: {percent * 100f:F1}%");
            yield return null;
        }

        if (downloadHandle.Status == AsyncOperationStatus.Succeeded)
            Debug.Log("다운로드 완료");
        else
            Debug.LogError("다운로드 실패");

        Addressables.Release(downloadHandle);
    }
}

4-4. 씬을 Addressables로 로드

대형 스테이지 씬을 Addressable Scene으로 만들어 원격에서 다운로드 후 로드할 수도 있습니다.

using System.Collections;
using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;
using UnityEngine.ResourceManagement.ResourceProviders;
using UnityEngine.SceneManagement;

public class AddressableSceneLoader : MonoBehaviour
{
    [SerializeField] private string m_sceneAddress = "scene/stage_01";

    private AsyncOperationHandle<SceneInstance> m_sceneHandle;

    public IEnumerator LoadStageScene()
    {
        m_sceneHandle = Addressables.LoadSceneAsync(m_sceneAddress, LoadSceneMode.Single);
        yield return m_sceneHandle;

        if (m_sceneHandle.Status != AsyncOperationStatus.Succeeded)
            Debug.LogError($"Scene Load Failed: {m_sceneAddress}");
    }
}

5. 메모리 관리: Load했으면 Release해야 합니다

Addressables는 로드된 에셋과 Bundle을 참조 카운트(reference count)로 관리합니다. Load하면 카운트가 올라가고, Release하면 내려갑니다. 카운트가 0이 되어야 언로드 대상이 됩니다.

그림 4. Addressables 메모리 관리는 참조 카운트와 Bundle 단위 언로드를 함께 이해해야 합니다.

좋은 습관

  • LoadAssetAsync를 호출했다면 나중에 Addressables.Release(handle)를 호출합니다.
  • InstantiateAsync를 사용했다면 나중에 Addressables.ReleaseInstance를 호출합니다.
  • 다운로드 진행률은 Loading UI에서 보여줍니다.
  • 스테이지가 끝나면 해당 스테이지 전용 에셋을 해제합니다.

자주 하는 실수

  • 로드만 하고 Release를 하지 않아 메모리가 계속 늘어나는 경우
  • 너무 많은 에셋을 한 Bundle에 넣어서 작은 에셋 하나 때문에 큰 Bundle이 계속 남는 경우
  • Remote 에셋을 게임 시작 즉시 전부 다운로드해서 초기 로딩이 길어지는 경우
  • 주소 문자열을 코드 여러 곳에 하드코딩해서 오타가 나는 경우

6. 콘텐츠 업데이트는 어떻게 되나요?

앱을 새로 배포하지 않고 서버에 있는 Addressable 콘텐츠만 교체하고 싶다면, Remote Catalog와 Content Update Build 흐름을 이해해야 합니다.

그림 5. Remote Catalog와 hash가 최신 콘텐츠 위치를 알려주는 핵심 파일입니다.

콘텐츠 업데이트 기본 흐름

  1. 처음 출시할 때 Build > New Build > Default Build Script로 전체 Addressables 콘텐츠를 빌드합니다.
  2. 이때 생성된 addressables_content_state.bin 파일을 반드시 보관합니다.
  3. 나중에 에셋을 수정합니다.
  4. Check for Content Update Restrictions를 실행해 업데이트 제한을 확인합니다.
  5. Build > Update a Previous Build로 업데이트 빌드를 만듭니다.
  6. 새로 나온 Remote Catalog, hash, 변경 Bundle을 서버에 업로드합니다.
  7. 기존 앱은 실행 시 변경된 Catalog를 확인하고 필요한 새 Bundle을 다운로드합니다.
실무 주의: Player를 새로 빌드해서 출시하는 경우와 기존 Player를 업데이트하는 경우의 Addressables 빌드 흐름을 섞으면 Catalog/Bundle 불일치가 생길 수 있습니다. 출시 기준이 되는 addressables_content_state.bin 파일을 버전별로 보관하는 습관이 중요합니다.

Group을 나눌 때 판단 기준

같이 묶으면 좋은 것

  • 항상 함께 로드되는 에셋
  • 같은 스테이지에서만 쓰는 에셋
  • 같은 이벤트 기간에만 쓰는 에셋
  • 같은 언어팩, 같은 스킨팩

분리하면 좋은 것

  • 용량이 큰 BGM/Voice
  • 자주 수정되는 이벤트 이미지
  • 일부 유저만 사용하는 고해상도 리소스
  • 각 스테이지별 독립 리소스
초보자에게 추천하는 첫 구조:
처음에는 Local_Common, Remote_Stage, Remote_Skin, Remote_Audio 정도로 단순하게 시작하세요. 이후 Profiler와 Build Report를 보면서 너무 큰 Bundle, 중복 에셋, 자주 바뀌는 에셋을 기준으로 세분화하는 방식이 안전합니다.
