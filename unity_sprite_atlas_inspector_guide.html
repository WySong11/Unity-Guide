1. Sprite Atlas 핵심 개념

Sprite Atlas는 여러 장의 Sprite 이미지를 한 장의 큰 Texture로 묶는 기능입니다. Unity는 이 큰 Texture 안에서 필요한 부분만 잘라서 Sprite처럼 보여줍니다.

Inspector는 무엇을 정하는 곳인가?

Sprite Atlas Inspector는 단순히 이미지를 넣는 곳이 아닙니다. 여기에서는 Atlas의 성격, Packing 방식, Texture 품질, 압축 방식, 빌드 포함 여부를 정합니다.

1. 기본 설정
   Type, Scriptable Packer, Include in Build

2. Packing 설정
   Allow Rotation, Tight Packing, Alpha Dilation, Padding

3. Texture 설정
   Read/Write, Mip Maps, sRGB, Filter Mode

4. Platform 설정
   Max Texture Size, Format, Compression, Crunch

5. Objects for Packing
   실제로 Atlas에 넣을 Sprite/폴더

3. 기본 설정

Type
현재 예시: Master

Atlas의 종류를 정합니다. Master는 실제 Sprite들을 직접 담는 기본 Atlas입니다. 대부분의 프로젝트에서는 Master를 사용합니다.

Variant는 Master Atlas를 기반으로 만든 축소/변형 버전입니다.

Master Atlas
원본 2048
→
Variant Atlas
축소 1024
추천: 일반 2D 게임 / 수업용 프로젝트는 Master 사용
Scriptable Packer
현재 예시: None

Atlas를 Packing할 때 사용할 커스텀 배치 로직을 지정하는 곳입니다.

None
→ Unity 기본 방식으로 자동 배치

Custom Scriptable Packer
→ 고급 사용자가 직접 만든 Packing 규칙 사용
추천: None 유지

현재 예시: On

이 Atlas를 게임 빌드에 포함할지 정합니다. Scene에서 SpriteRenderer, UI Image, Tilemap 등이 이 Sprite들을 사용한다면 보통 켜야 합니다.

4. Packing 옵션

Packing은 Sprite들을 Atlas 안에 어떻게 배치할지 정하는 영역입니다.

Allow Rotation
현재 예시: Off

Atlas 공간을 더 아끼기 위해 Sprite를 90도 회전해서 배치해도 되는지 정합니다.

Off: 원래 방향 유지
긴 발판 Sprite

방향이 바뀌지 않아 안전함

On: 회전 가능
회전된
발판

공간은 아끼지만 UI에는 위험할 수 있음

UI Image에 들어갈 Sprite는 회전 Packing 때문에 방향 문제가 생길 수 있으므로 보통 Off가 안전합니다.
추천: UI 또는 초보자 프로젝트는 Off
Tight Packing
현재 예시: Off

Sprite를 사각형 기준으로 넣을지, 실제 이미지 외곽선에 가깝게 넣을지 정합니다.

Off: 사각형 기준
🐉

타일, 패널, UI 배경에 안전

On: 외곽선 기준
🐉

투명 영역이 많은 이미지에 유리

타일맵, 바닥 블록, UI 패널처럼 정확한 사각형 형태가 중요한 Sprite는 Off가 안전합니다.

추천: 타일/발판/패널이 많으면 Off
Alpha Dilation
현재 예시: Off

투명 영역 주변으로 색을 살짝 확장해서 가장자리 이물질/흰선/검은선을 줄이는 옵션입니다.

문제 상황

Sprite 주변에 검은/흰 줄이 보임

Alpha Dilation 테스트

투명 경계 쪽 색 번짐 완화

추천: 가장자리 선 문제가 보이면 On 테스트
Padding
현재 예시: 4

Atlas 안에서 Sprite와 Sprite 사이에 두는 간격입니다.

Padding이 너무 작을 때

옆 Sprite 색이 새어 보일 수 있음

Padding 4~8

타일 경계선 문제를 줄임

추천: 기본 4, 타일 경계선 문제가 있으면 8

5. Texture 옵션

Texture 영역은 Atlas가 최종적으로 만들어질 때의 품질, 색상, 필터링, 메모리를 정합니다.

Read/Write
현재 예시: Off

C# 코드에서 Texture 픽셀을 직접 읽거나 수정할 수 있게 할지 정합니다.

texture.GetPixels();
texture.SetPixels();
texture.Apply();

이런 코드를 쓰지 않는다면 필요 없습니다. 켜면 메모리 사용량이 늘 수 있습니다.

추천: 일반 Sprite/UI는 Off
Generate Mip Maps
현재 예시: Off

Mip Map은 Texture의 여러 축소 버전을 미리 만들어두는 기능입니다.

2048 원본
→
1024
→
512
→
256

3D 공간에서 멀어지는 오브젝트에는 유용하지만, 2D 픽셀아트나 UI에서는 흐릿하게 보일 수 있습니다.

추천: 2D 픽셀아트/UI는 Off
sRGB
현재 예시: On

이 Texture를 일반 색상 이미지로 처리할지 정합니다.

켜는 경우끄는 경우
캐릭터 Sprite, 배경, 타일, UI 아이콘Normal Map, Mask Texture, 특수 셰이더 데이터 Texture
추천: 일반 Sprite Atlas는 On
Filter Mode
현재 예시: Point

Sprite가 확대/축소될 때 픽셀을 어떻게 보여줄지 정합니다.

Point

픽셀아트용. 선명하지만 계단 현상이 보입니다.

Bilinear

일반 UI/일러스트용. 부드럽지만 픽셀아트가 흐릿해질 수 있습니다.

Trilinear

Mip Map과 함께 사용. 2D 픽셀 게임에서는 거의 필요 없습니다.

추천: 픽셀아트는 Point, 일반 UI는 Bilinear

6. Platform 설정

Platform Settings는 최종 Atlas Texture의 최대 크기, 압축 포맷, 압축 품질을 정합니다.

Max Texture Size
현재 예시: 2048

Atlas Texture가 가질 수 있는 최대 크기입니다.

1024
작은 UI용
→
2048
일반 2D 게임
→
4096
고해상도 많을 때

너무 작으면 Atlas가 여러 장으로 나뉠 수 있고, 너무 크면 메모리 부담이 커질 수 있습니다.

추천: 현재 같은 2D 캐릭터/타일 프로젝트는 2048 적절
Format
현재 예시: Automatic

플랫폼별 Texture 압축 포맷을 정합니다. Automatic이면 Unity가 플랫폼에 맞게 자동 선택합니다.

Windows / Standalone → DXT 계열
Android              → ETC2 / ASTC 등
iOS                  → PVRTC / ASTC 등
WebGL                → 플랫폼 상황에 맞게 처리
추천: 초보자/일반 프로젝트는 Automatic
Compression
현재 예시: Normal Quality

Texture 압축 품질을 정합니다.

값특징추천 상황
None압축하지 않음. 가장 선명하지만 용량 증가픽셀아트 품질이 중요할 때
Normal Quality용량과 품질의 균형일반 테스트/수업용
High Quality품질을 더 중시압축은 유지하되 품질을 올리고 싶을 때
픽셀아트가 뭉개지거나 색이 지저분하면 Compression을 None으로 바꿔서 비교해보세요.
Use Crunch Compression
현재 예시: Off

빌드 파일 용량을 더 줄이기 위한 손실 압축입니다. 용량은 줄일 수 있지만, 이미지 품질 손상이나 압축 해제 비용이 있을 수 있습니다.

추천: 픽셀아트/UI는 Off

8. 현재 화면 기준 추천 설정

스크린샷처럼 픽셀아트 2D 게임, 타일, 캐릭터 Sprite가 들어간 Atlas라면 아래 설정이 무난합니다.

Type: Master
Include in Build: On
Allow Rotation: Off
Tight Packing: Off
Alpha Dilation: 문제 있을 때 On 테스트
Padding: 4 또는 8
Read/Write: Off
Generate Mip Maps: Off
sRGB: On
Filter Mode: Point
Max Texture Size: 2048
Format: Automatic
Compression: None 또는 Normal Quality
Use Crunch Compression: Off
가장 먼저 확인할 3가지
1순위

Filter Mode = Point

픽셀아트가 흐릿하게 보이면 가장 먼저 확인합니다.

2순위

Padding = 4~8

타일 사이에 얇은 선이 생기면 Padding을 올려봅니다.

3순위

Compression = None 테스트

색이 지저분하거나 경계가 깨지면 압축을 꺼서 비교합니다.

최종 결론: 현재 설정은 대부분 적절합니다. 픽셀아트가 선명해야 하므로 Filter Mode는 Point가 좋고, 타일 경계선 문제가 생기면 Padding을 8로 올려보세요. 그래도 지저분하면 Compression을 None으로 바꿔 비교하면 됩니다.
