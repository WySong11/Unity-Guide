전체 구조 한눈에 보기

제공된 그래프는 크게 보면 아래 순서로 작동합니다. 처음부터 모든 노드를 외우려고 하기보다, “이미지 주변을 검사해서 가장자리만 찾는다”는 큰 흐름을 먼저 잡으면 이해가 쉽습니다.

1. 원본 읽기Sprite Texture를 Sample Texture 2D로 읽습니다.
2. 주변 읽기UV를 조금씩 옮겨서 위, 아래, 왼쪽, 오른쪽 픽셀을 다시 읽습니다.
3. 마스크 만들기주변에는 그림이 있는데 현재 픽셀은 투명한 곳을 외곽선 후보로 잡습니다.
4. 색/알파 적용OutlineColor, OutlineAlpha, Blink 값을 곱해 외곽선 색을 만듭니다.
5. 최종 출력원본 스프라이트와 외곽선을 Add해서 Fragment에 연결합니다.

이 그래프가 하려는 일

핵심 목표

원본 스프라이트는 그대로 보여주고, 원본 이미지의 바깥쪽 투명 영역에만 외곽선을 추가하는 것입니다.

예를 들어 바이킹 얼굴 이미지가 있다고 할 때, 얼굴 자체는 그대로 출력하고 얼굴 주변 투명 픽셀 중에서 얼굴과 가까운 부분만 주황색 외곽선으로 칠합니다.

최종 색 = 원본 스프라이트 색 + 외곽선 색
외곽선 색 = 외곽선 마스크 × OutlineColor × OutlineAlpha × 깜빡임 값

여기서 가장 중요한 단어는 마스크입니다. 마스크는 “어디를 칠할지 정하는 흑백 지도”라고 생각하면 됩니다. 흰색이면 칠하고, 검은색이면 칠하지 않습니다.

1단계: 원본 스프라이트 읽기

Shader Graph에서 이미지를 읽을 때는 보통 Sample Texture 2D 노드를 사용합니다. 이 노드는 텍스처와 UV 좌표를 받아서 해당 위치의 색을 반환합니다.

개념쉬운 설명
Texture2D이미지 파일입니다. 여기서는 바이킹 스프라이트입니다.
UV이미지를 읽는 좌표입니다. 왼쪽 아래가 보통 0,0이고 오른쪽 위가 1,1입니다.
RGBAR/G/B는 색, A는 투명도입니다. 외곽선 계산에서는 특히 A, 즉 Alpha가 중요합니다.
투명 PNG의 바깥쪽은 Alpha가 0에 가깝고, 캐릭터가 있는 부분은 Alpha가 1에 가깝습니다. 이 Alpha 차이를 이용하면 “그림이 있는 부분”과 “투명한 부분”을 구분할 수 있습니다.

2단계: 주변 픽셀을 여러 번 읽기

외곽선을 만들려면 현재 픽셀만 보면 부족합니다. 현재 픽셀이 투명하더라도, 바로 옆 픽셀에 그림이 있으면 그 위치는 외곽선이 될 수 있습니다.

그래서 그래프 왼쪽에서는 UV 좌표를 조금 움직여서 여러 방향의 픽셀을 샘플링합니다.

방향UV 계산의미
오른쪽 검사UV + (OffsetX, 0)현재 위치보다 오른쪽에 그림이 있는지 봅니다.
왼쪽 검사UV + (-OffsetX, 0)현재 위치보다 왼쪽에 그림이 있는지 봅니다.
위쪽 검사UV + (0, OffsetY)현재 위치보다 위쪽에 그림이 있는지 봅니다.
아래쪽 검사UV + (0, -OffsetY)현재 위치보다 아래쪽에 그림이 있는지 봅니다.
주변 Alpha = 오른쪽 Alpha + 왼쪽 Alpha + 위쪽 Alpha + 아래쪽 Alpha

여러 방향을 읽는 이유는 외곽선이 한쪽에만 생기지 않고 캐릭터 전체 둘레에 생기게 하기 위해서입니다.

3단계: 외곽선 마스크 만들기

주변 픽셀을 읽었다면 이제 “외곽선을 칠할 위치”를 골라야 합니다. 기준은 다음과 같습니다.

외곽선이 필요한 곳

현재 픽셀은 투명하지만, 주변 픽셀에는 그림이 있는 곳입니다.

외곽선이 필요 없는 곳

현재 픽셀이 이미 원본 그림 안쪽인 곳입니다. 이곳까지 외곽선을 칠하면 원본 색을 덮어버립니다.

외곽선 후보 = 주변 Alpha 중 가장 큰 값
외곽선 마스크 = 외곽선 후보 - 원본 Alpha

이 계산의 의미는 간단합니다. 주변에는 그림이 있어서 후보 값은 크지만, 현재 위치의 원본 Alpha가 0이면 외곽선이 됩니다. 반대로 현재 위치가 이미 원본 그림 안쪽이면 원본 Alpha가 크기 때문에 외곽선 값이 줄어듭니다.

그래프에서 실제로는 Add, Maximum, Subtract, Saturate 같은 노드를 조합해서 이 값을 안정적으로 만듭니다. Saturate는 값을 0~1 범위 안으로 잘라주는 안전장치입니다.

4단계: 깜빡이는 외곽선 만들기

아래쪽 노드 묶음은 외곽선의 투명도를 시간에 따라 바꾸는 부분입니다. 즉, 외곽선이 은은하게 깜빡이도록 만듭니다.

노드/값역할
Time시간이 계속 증가하는 값입니다. 애니메이션의 기준이 됩니다.
OutlineBlinkSpeed깜빡이는 속도입니다. 값이 클수록 빠르게 깜빡입니다.
Sine값을 부드럽게 오르내리게 합니다. 딱딱하게 켜졌다 꺼지는 것이 아니라 숨 쉬듯 변합니다.
OutlineBlinkStrength깜빡임의 강도입니다. 값이 클수록 투명도 변화 폭이 커집니다.
OutlineBlinkMinAlpha가장 어두워졌을 때도 남겨둘 최소 투명도입니다.
깜빡임 값 = MinAlpha와 1 사이를 시간에 따라 왕복하는 값

외곽선이 완전히 사라지면 눈에 거슬릴 수 있으므로 OutlineBlinkMinAlpha로 최소 밝기를 남겨두는 구조입니다.

5단계: 원본과 외곽선을 합쳐 출력하기

오른쪽 끝에서는 지금까지 만든 외곽선 색과 원본 스프라이트 색을 합쳐서 최종 결과를 출력합니다.

외곽선 색 = OutlineColor × 외곽선 마스크 × OutlineAlpha × 깜빡임 값
최종 Base Color = 원본 색 + 외곽선 색

그래프의 오른쪽 미리보기처럼 원본 그림은 그대로 보이고, 바깥쪽에 주황색 외곽선이 생기는 이유가 바로 이 합성 단계 때문입니다.

원본 스프라이트의 Alpha를 유지하면서 외곽선 Alpha를 더해주면, 투명 배경은 계속 투명하게 남고 외곽선이 필요한 부분만 보입니다.

Inspector 프로퍼티 설명

프로퍼티역할추천 시작값

OutlineColor외곽선 색입니다.주황, 노랑, 흰색처럼 원본과 대비되는 색

입문자용 비유로 이해하기

UV Offset은 무엇인가?

현재 픽셀에서 “한 칸 옆을 살짝 보는 것”입니다. 오른쪽, 왼쪽, 위, 아래를 살펴보고 근처에 그림이 있으면 현재 위치가 가장자리일 가능성이 높다고 판단합니다.

Alpha는 왜 중요한가?

투명 PNG에서 Alpha는 그림이 있는지 없는지를 알려주는 지도입니다. 색보다 Alpha를 보는 이유는 외곽선은 색의 경계가 아니라 투명 영역과 불투명 영역의 경계를 찾아야 하기 때문입니다.

그래프를 직접 만들 때의 추천 순서

  1. SpriteTexture 프로퍼티를 만들고 Sample Texture 2D로 원본을 출력합니다.
  2. UV 노드를 만들고, Vector2로 오른쪽/왼쪽/위/아래 Offset을 만듭니다.
  3. 각 Offset UV를 Sample Texture 2D에 연결해서 Alpha만 꺼냅니다.
  4. 여러 Alpha를 Maximum 또는 Add로 합칩니다.
  5. 원본 Alpha를 빼서 안쪽은 지우고 바깥쪽만 남깁니다.
  6. Saturate로 0~1 범위로 정리합니다.
  7. OutlineColor, OutlineAlpha를 곱합니다.
  8. 원본 색과 외곽선 색을 더해서 Fragment 출력에 연결합니다.

자주 생기는 문제와 해결법

문제원인해결
외곽선이 너무 얇다Offset 또는 OutlineThickness가 작음OutlineThickness를 조금씩 올립니다.
외곽선이 깨져 보인다샘플 방향이 적거나 텍스처 해상도가 낮음대각선 방향 샘플을 추가하거나 원본 해상도를 확인합니다.
원본 그림 안쪽까지 색이 번진다원본 Alpha를 제대로 빼지 않았거나 Saturate가 없음외곽선 후보 - 원본 Alpha 구조를 확인합니다.
스프라이트 주변 사각형이 보인다투명 배경 처리 또는 Alpha 출력 문제Fragment Alpha 연결, Blend 설정, Sprite 텍스처 Alpha를 확인합니다.
Inspector에서 값 조절이 안 된다Property가 Blackboard에 없거나 Exposed가 꺼짐Property의 Exposed/Show In Inspector 설정을 확인합니다.

최종 요약

이 Shader Graph의 핵심은 “현재 픽셀 주변에 원본 이미지가 있는지 검사해서, 투명 영역 중 가장자리만 외곽선으로 칠하는 것”입니다.

입문자는 먼저 Sample Texture 2D, UV Offset, Alpha, Mask, Add 이 다섯 개만 이해하면 전체 구조를 따라갈 수 있습니다.

작성 기준: 제공된 Shader Graph 캡처 이미지. Unity/Shader Graph 버전에 따라 노드 이름이나 Inspector 표시 방식은 약간 다를 수 있습니다.
