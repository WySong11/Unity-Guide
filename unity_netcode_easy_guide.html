Unity Netcode 쉽게 이해하기

멀티플레이 게임에서 누가 조작하고, 누가 판단하고, 그 결과를 어떻게 모두에게 보여줄지를 관리하는 시스템입니다.

Netcode for GameObjects NetworkManager RPC NetworkVariable NetworkTransform

1. Netcode가 왜 필요할까?

싱글플레이에서는 내 컴퓨터에서 오브젝트를 움직이면 끝입니다. 하지만 멀티플레이에서는 다른 플레이어의 컴퓨터에도 같은 결과가 보여야 합니다.

핵심: 클라이언트는 요청하고, 서버는 검증하고, 확정된 결과를 모든 클라이언트에게 동기화합니다.

2. Unity Netcode의 핵심 구성 요소

Unity Netcode는 GameObject / MonoBehaviour 방식에 네트워크 기능을 붙이는 구조입니다. 아래 6개만 먼저 이해하면 전체 그림이 보입니다.

🕹️
NetworkManager

Host, Server, Client 실행을 관리합니다. 플레이어 프리팹, Transport, 접속 상태도 여기서 관리합니다.

⬢
NetworkObject

“이 오브젝트는 네트워크에서 공유되는 오브젝트입니다”라는 표시입니다.

🧩
NetworkBehaviour

RPC, NetworkVariable, IsOwner, IsServer 같은 Netcode 기능을 쓰는 스크립트입니다.

❤️
NetworkVariable

HP, 점수, 준비 상태처럼 계속 유지되어야 하는 값을 자동 동기화합니다.

⚡
RPC

다른 컴퓨터에서 함수를 실행시키는 요청입니다. 공격, 점프, 이펙트처럼 순간 이벤트에 적합합니다.

↔️
NetworkTransform

위치, 회전, 크기를 동기화합니다. 입문 단계의 플레이어 위치 동기화에 자주 사용합니다.

3. Client, Server, Owner 쉽게 구분하기

💻

Client

플레이어가 실제로 조작하는 쪽입니다. 입력, 카메라, UI 같은 로컬 기능을 처리합니다.

  • 키보드 / 조이스틱 입력
  • 내 카메라 추적
  • 내 HP UI 표시
🛡️

Server

게임의 중요한 결과를 최종 확정하는 쪽입니다. 치트 방지를 위해 핵심 판정은 서버가 담당하는 것이 안전합니다.

  • 데미지 판정
  • 점수 처리
  • 아이템 획득 확정
👤

Owner

특정 NetworkObject를 조작할 권한이 있는 클라이언트입니다. 보통 내 플레이어 캐릭터의 Owner는 나입니다.

  • IsOwner가 true인 오브젝트만 입력 처리
  • 다른 사람 캐릭터는 입력 처리 금지
⭐
입문자 공식
내 캐릭터 입력은 IsOwner로 제한하고, HP/점수/승패 같은 중요한 값 변경은 IsServer에서 처리합니다.

4. 데이터 흐름 그림으로 보기

예를 들어 플레이어가 공격 버튼을 눌렀을 때의 흐름입니다.

1

플레이어 입력

클라이언트에서 마우스 클릭 또는 공격 버튼 입력이 발생합니다.

2

RPC 요청

클라이언트가 서버에게 “공격하고 싶다”고 요청합니다.

3

서버 판정

서버가 거리, 쿨타임, 명중 여부, 데미지를 검사합니다.

4

값 변경

서버가 HP, 점수, 상태값을 변경합니다.

5

전체 동기화

변경된 결과가 모든 클라이언트 화면에 반영됩니다.

5. 언제 무엇을 써야 할까?

기능 사용하는 경우 예시 기억법
NetworkVariable 계속 유지되어야 하는 상태값 HP, 점수, 준비 완료, 현재 무기 번호, 문 열림 상태 “값이 남아 있어야 하면 NetworkVariable”
RPC 순간적으로 발생하는 이벤트나 요청 공격 요청, 점프 요청, 이펙트 재생, 사운드 재생 “한 번 발생하고 끝나면 RPC”
NetworkTransform Transform 정보 동기화 플레이어 위치, 회전, 크기 “움직임을 보여줘야 하면 NetworkTransform”

6. 가장 기본 코드 예시

아래 코드는 “내 캐릭터만 입력을 받고 움직이게 하는” 가장 기본 구조입니다.

using Unity.Netcode;
using UnityEngine;

public class PlayerMove : NetworkBehaviour
{
    [SerializeField] private float speed = 5f;

    private void Update()
    {
        // 이 오브젝트의 주인이 내가 아니면 입력을 처리하지 않습니다.
        if (!IsOwner)
        {
            return;
        }

        float x = Input.GetAxisRaw("Horizontal");
        float z = Input.GetAxisRaw("Vertical");

        Vector3 move = new Vector3(x, 0f, z).normalized;
        transform.position += move * speed * Time.deltaTime;
    }
}

그리고 서버에게 공격을 요청하는 구조는 아래처럼 생각하면 됩니다.

using Unity.Netcode;
using UnityEngine;

public class PlayerAttack : NetworkBehaviour
{
    private void Update()
    {
        if (!IsOwner)
        {
            return;
        }

        if (Input.GetMouseButtonDown(0))
        {
            RequestAttackRpc();
        }
    }

    // 클라이언트가 서버에게 공격 처리를 요청합니다.
    [Rpc(SendTo.Server)]
    private void RequestAttackRpc()
    {
        // 서버에서 실제 공격 판정, 데미지 계산, HP 감소를 처리합니다.
        Debug.Log("서버에서 공격 판정");

        PlayAttackEffectRpc();
    }

    // 서버가 클라이언트들에게 이펙트 재생을 요청합니다.
    [Rpc(SendTo.NotServer)]
    private void PlayAttackEffectRpc()
    {
        Debug.Log("클라이언트에서 공격 이펙트 재생");
    }
}

7. 입문자가 자주 하는 실수 체크리스트

  • NetworkObject를 안 붙임 — 네트워크 오브젝트로 관리할 프리팹에는 필요합니다.
  • 모든 플레이어가 입력을 받음 — 입력 코드는 보통 if (!IsOwner) return;으로 막아야 합니다.
  • 클라이언트가 HP를 직접 변경함 — 데미지, 점수, 사망은 서버에서 확정하는 구조가 안전합니다.
  • UI와 카메라까지 네트워크 동기화하려 함 — UI와 카메라는 대부분 로컬 전용입니다.
  • RPC와 NetworkVariable을 반대로 사용함 — 상태는 NetworkVariable, 순간 이벤트는 RPC로 생각하면 쉽습니다.
  • Host에서는 되는데 Client에서는 안 됨 — Host는 서버와 클라이언트를 동시에 갖기 때문에 권한 문제가 숨겨질 수 있습니다.

Unity Netcode는 멀티플레이 게임에서 “누가 조작하고, 누가 판단하고, 어떻게 모두에게 보여줄지”를 관리하는 Unity 공식 네트워크 시스템입니다.

추천 학습 순서

1 NetworkManager 만들기 → 2 Host/Client 실행 → 3 Player Prefab 등록 → 4 NetworkObject 붙이기 → 5 IsOwner로 입력 제한 → 6 NetworkTransform → 7 NetworkVariable → 8 RPC → 9 서버 권위 데미지 처리

기준: Netcode for GameObjects 최신 릴리스 계열. 실제 프로젝트에서는 사용 중인 Unity 버전과 패키지 버전을 확인한 뒤 API 이름을 맞춰 사용하세요.
