1. Addressables Remote Content Distribution이란?

Addressables Remote Content Distribution은 게임 설치 파일에는 꼭 필요한 최소 에셋만 넣고, 추가 캐릭터, 스테이지, 스킨, 사운드, 이벤트 리소스 같은 큰 에셋은 서버에 올려두었다가 필요할 때 다운로드하는 구조입니다.

한 줄 정의:
앱에는 LoadingScene, 기본 UI, 다운로드 시스템만 넣고, 서버에는 추가 콘텐츠 AssetBundle을 올려둔 뒤, 게임 실행 중 GetDownloadSizeAsync → DownloadDependenciesAsync → LoadAssetAsync 순서로 사용하는 방식입니다.
일반 빌드 방식

게임에서 쓸 가능성이 있는 에셋을 대부분 앱 안에 넣습니다.

  • 설치 용량이 커질 수 있음
  • 처음부터 모든 리소스를 가지고 있음
  • 리소스 업데이트를 하려면 앱 업데이트가 필요한 경우가 많음
Remote Addressables 방식

처음에는 필수 에셋만 가지고 시작하고, 필요한 콘텐츠만 서버에서 받습니다.

  • 초기 설치 용량을 줄일 수 있음
  • 스테이지, 스킨, 사운드를 나중에 추가 가능
  • 라이브 서비스형 콘텐츠 운영에 유리함

Catalog는 주소록입니다

Addressables에서 Catalog는 “주소와 실제 파일 위치를 연결해주는 주소록”입니다. 코드에서는 Stage_01이라는 주소만 요청하지만, Catalog는 그 주소가 어느 Bundle 안에 있고 어디서 받아야 하는지 알려줍니다.

2단계: Group을 Local과 Remote로 나누기

입문자에게 추천하는 Group 구조입니다.

Group 이름 위치 넣을 에셋
Local_Core 앱 안 LoadingScene, 기본 UI, 기본 폰트, 다운로드 팝업, Manager
Remote_Stages 서버 추가 스테이지 Scene, 스테이지 배경, 맵 리소스

중요: 다운로드 화면에 필요한 리소스는 Remote로 빼면 안 됩니다. 예를 들어 기본 폰트, 다운로드 팝업 배경, 재시도 버튼 아이콘까지 Remote에 있으면 인터넷이 안 될 때 화면 자체가 깨질 수 있습니다.

3단계: Remote Catalog 켜기

Addressables Settings에서 다음 옵션을 켭니다.

  • Build Remote Catalog 체크
  • Remote Catalog의 Build Path / Load Path를 Remote 쪽으로 설정

Remote Catalog를 켜야 앱이 서버에 올라간 새 Catalog를 확인하고, 어떤 Bundle을 다운로드해야 하는지 알 수 있습니다.

RemoteBuildPath내 PC에 생성되는 업로드용 파일 위치

5단계: Remote Group의 Path 설정

Remote로 받을 Group은 다음처럼 설정합니다.

  • Build Path = RemoteBuildPath
  • Load Path = RemoteLoadPath

반대로 앱에 포함할 Local_Core는 Local Path를 사용합니다.

4. 런타임 다운로드 흐름

게임 실행 중에는 바로 LoadAssetAsync부터 호출하기보다, 먼저 다운로드가 필요한지 확인하고, 필요할 때만 다운로드한 뒤 로드하는 구조가 좋습니다.

그림 5. 실제 게임 실행 중 흐름
게임 시작Local LoadingScene 실행
→
Catalog 확인CheckForCatalogUpdates
→
콘텐츠 선택Stage_01 클릭
→

→

핵심 API 4개

API 역할 언제 쓰나?
CheckForCatalogUpdates 서버에 새 Catalog가 있는지 확인 게임 시작, 타이틀 화면, 업데이트 확인 화면
UpdateCatalogs 새 Catalog를 받아서 주소록 갱신 새 리소스나 변경된 리소스를 반영할 때
GetDownloadSizeAsync 다운로드가 필요한 용량 확인 다운로드 팝업을 띄우기 전
DownloadDependenciesAsync 해당 Address 또는 Label에 필요한 Bundle 다운로드 콘텐츠 입장 전 사전 다운로드
추천 흐름:
Stage_01에 들어가기 전에 GetDownloadSizeAsync("Stage_01")로 크기를 확인합니다. 결과가 0이면 이미 캐시에 있는 것이므로 바로 로드합니다. 0보다 크면 다운로드 팝업을 띄운 뒤 DownloadDependenciesAsync("Stage_01")를 실행합니다.

Address 하나만 받기 vs Label로 묶어서 받기

Address 하나만 다운로드
DownloadDependenciesAsync("Enemy_Goblin")

특정 프리팹이나 특정 스테이지 하나만 받을 때 사용하기 쉽습니다.

Label로 여러 에셋 묶음 다운로드
DownloadDependenciesAsync("Stage_01")

Stage_01에 필요한 Scene, BGM, Enemy, Background를 같은 Label로 묶어 한 번에 받을 수 있습니다.

5. 예시 코드

아래 코드는 입문자용 기본 구조입니다. 실제 프로젝트에서는 UI Slider, 팝업, 네트워크 재시도 버튼과 연결해서 사용하면 됩니다.

AddressableDownloadManager.cs

using System;
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

public class AddressableDownloadManager : MonoBehaviour
{
    public static AddressableDownloadManager Instance { get; private set; }

    private void Awake()
    {
        if (Instance != null)
        {
            Destroy(gameObject);
            return;
        }

        Instance = this;
        DontDestroyOnLoad(gameObject);
    }

    // 서버에 새 Catalog가 있는지 확인하고, 있으면 갱신합니다.
    public IEnumerator UpdateCatalogIfNeeded()
    {
        AsyncOperationHandle<List<string>> checkHandle =
            Addressables.CheckForCatalogUpdates();

        yield return checkHandle;

        if (checkHandle.Status != AsyncOperationStatus.Succeeded)
        {
            Debug.LogWarning("Catalog 업데이트 확인 실패");
            Addressables.Release(checkHandle);
            yield break;
        }

        List<string> catalogs = checkHandle.Result;

        if (catalogs != null && catalogs.Count > 0)
        {
            AsyncOperationHandle<List<UnityEngine.ResourceManagement.ResourceLocations.IResourceLocator>> updateHandle =
                Addressables.UpdateCatalogs(catalogs);

            yield return updateHandle;

            if (updateHandle.Status == AsyncOperationStatus.Succeeded)
                Debug.Log("Catalog 업데이트 완료");
            else
                Debug.LogWarning("Catalog 업데이트 실패");

            Addressables.Release(updateHandle);
        }
        else
        {
            Debug.Log("업데이트할 Catalog 없음");
        }

        Addressables.Release(checkHandle);
    }

    // key에는 Address 또는 Label을 넣을 수 있습니다.
    public IEnumerator DownloadIfNeeded(
        object key,
        Action<long> onSizeChecked = null,
        Action<float> onProgress = null,
        Action<bool> onComplete = null)
    {
        // 1. 먼저 다운로드해야 할 용량을 확인합니다.
        AsyncOperationHandle<long> sizeHandle = Addressables.GetDownloadSizeAsync(key);

        yield return sizeHandle;

        if (sizeHandle.Status != AsyncOperationStatus.Succeeded)
        {
            Debug.LogWarning("다운로드 크기 확인 실패: " + key);
            Addressables.Release(sizeHandle);
            onComplete?.Invoke(false);
            yield break;
        }

        long downloadSize = sizeHandle.Result;
        onSizeChecked?.Invoke(downloadSize);
        Addressables.Release(sizeHandle);

        // 2. 이미 다운로드되어 있으면 바로 성공 처리합니다.
        if (downloadSize <= 0)
        {
            Debug.Log("이미 다운로드되어 있음: " + key);
            onProgress?.Invoke(1f);
            onComplete?.Invoke(true);
            yield break;
        }

        // 3. 실제 다운로드를 시작합니다.
        AsyncOperationHandle downloadHandle = Addressables.DownloadDependenciesAsync(key);

        while (!downloadHandle.IsDone)
        {
            var status = downloadHandle.GetDownloadStatus();
            float progress = 0f;

            if (status.TotalBytes > 0)
                progress = status.Percent;
            else
                progress = downloadHandle.PercentComplete;

            onProgress?.Invoke(progress);
            yield return null;
        }

        bool success = downloadHandle.Status == AsyncOperationStatus.Succeeded;

        if (success)
            Debug.Log("다운로드 완료: " + key);
        else
            Debug.LogWarning("다운로드 실패: " + key);

        Addressables.Release(downloadHandle);
        onComplete?.Invoke(success);
    }
}

스테이지 버튼에서 사용하는 예시

using System.Collections;
using UnityEngine;
using UnityEngine.AddressableAssets;

public class StageEnterButton : MonoBehaviour
{
    [SerializeField] private string m_stageKey = "Stage_01";

    public void OnClickEnterStage()
    {
        StartCoroutine(EnterStageRoutine());
    }

    private IEnumerator EnterStageRoutine()
    {
        bool downloadSuccess = false;

        yield return AddressableDownloadManager.Instance.DownloadIfNeeded(
            m_stageKey,
            onSizeChecked: size =>
            {
                Debug.Log("필요 다운로드 용량: " + FormatBytes(size));
                // 여기에서 "다운로드가 필요합니다" 팝업을 띄울 수 있습니다.
            },
            onProgress: progress =>
            {
                Debug.Log("다운로드 진행률: " + (progress * 100f).ToString("F1") + "%");
                // 여기에서 UI Slider.value = progress; 처리
            },
            onComplete: success =>
            {
                downloadSuccess = success;
            }
        );

        if (downloadSuccess == false)
        {
            Debug.LogWarning("다운로드 실패. 스테이지 입장 취소.");
            yield break;
        }

        // Scene이 Addressable이라면 이렇게 로드할 수 있습니다.
        Addressables.LoadSceneAsync(m_stageKey);
    }

    private string FormatBytes(long bytes)
    {
        if (bytes < 1024)
            return bytes + " B";

        if (bytes < 1024 * 1024)
            return (bytes / 1024f).ToString("F1") + " KB";

        return (bytes / 1024f / 1024f).ToString("F1") + " MB";
    }
}

6. 서버 콘텐츠 업데이트 방식

Remote Addressables의 장점은 앱 전체를 다시 배포하지 않고도 서버의 리소스를 바꿀 수 있다는 점입니다. 단, C# 코드 자체는 AssetBundle로 업데이트할 수 없습니다. 스크립트 로직 변경은 일반 앱 업데이트가 필요합니다.

이 파일은 “이전에 출시했던 Addressables 콘텐츠 상태”를 기억하는 기준 파일입니다. 나중에 변경된 리소스만 패치 형태로 만들 때 필요합니다.

7. 자주 하는 실수 체크리스트

좋은 구성
  • LoadingScene과 다운로드 UI는 Local에 둔다.
  • 스테이지별 리소스는 Label로 묶는다.
  • Remote Group은 Build Path와 Load Path를 Remote로 둔다.
  • 다운로드 전 GetDownloadSizeAsync로 용량을 확인한다.
  • 플랫폼별로 Addressables Build를 따로 만든다.
  • 출시 시점의 addressables_content_state.bin을 보관한다.
위험한 구성
  • 다운로드 팝업 이미지나 폰트까지 Remote로 빼버린다.
  • 아이콘 하나마다 Bundle을 따로 만든다.
  • 자주 바뀌는 에셋과 거의 안 바뀌는 에셋을 같은 Bundle에 넣는다.
  • Addressables Build 없이 Player Build만 한다.
  • Android용 Bundle을 WebGL 서버 경로에 올린다.
  • Addressables로 C# 코드까지 업데이트할 수 있다고 착각한다.

WebGL에서 특히 조심할 점

WebGL에서 다른 도메인/CDN의 Bundle을 다운로드하려면 서버의 CORS 설정이 필요할 수 있습니다. 브라우저 보안 정책 때문에 URL은 맞는데도 다운로드가 막히는 경우가 있습니다.

Group을 나누는 기준

기준 추천
항상 필요한 리소스 Local Group
용량이 큰 리소스 Remote Group
나중에 추가될 리소스 Remote Group
자주 바뀌는 이벤트 리소스 별도 Remote Group
공통 Material, 공통 Font, 공통 Texture 중복 번들 방지를 위해 별도 관리 고려
