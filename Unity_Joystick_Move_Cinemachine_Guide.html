1. 최종 목표

캐릭터가 현재 바라보는 방향을 기준으로 조이스틱의 왼쪽·오른쪽·앞·뒤를 해석하고, 실제 이동 방향으로 캐릭터가 회전한 뒤 Cinemachine 카메라가 새 방향의 뒤쪽으로 따라오게 합니다.

원하는 동작

← 캐릭터가 바라보는 방향의 왼쪽으로 회전하고 이동

→ 캐릭터가 바라보는 방향의 오른쪽으로 회전하고 이동

↓ 캐릭터가 뒤쪽으로 돌아선 뒤 이동

카메라는 이동 중인 캐릭터의 뒤쪽을 유지

피해야 하는 동작

왼쪽 입력이 항상 월드 -X 방향으로 이동

오른쪽 입력이 항상 월드 +X 방향으로 이동

캐릭터 방향을 매 프레임 기준으로 다시 계산해 원을 그리며 회전

Face Move Direction을 꺼서 캐릭터가 정면만 바라봄

2. 현재 화면에서 확인되는 문제

화면에서 확인할 항목

Face Move Direction은 체크 상태여야 합니다.

Camera Transform에는 실제 카메라인 Main Camera를 연결하는 것이 안전합니다.

Rotation Speed는 보통 360~720 사이에서 조절합니다.

Move Dead Zone은 보통 0.1~0.15가 적당합니다.

이번 캐릭터 기준 이동 계산에서는 일반 이동에 카메라 방향을 직접 사용하지 않습니다. 하지만 Lock 모드나 Base 기능을 위해 Main Camera 연결은 권장합니다.

3. 월드 기준·카메라 기준·캐릭터 기준의 차이

기준 왼쪽 입력의 의미 특징
월드 기준 항상 월드 -X 캐릭터가 어느 방향을 보더라도 같은 축으로 이동합니다.
카메라 기준 현재 카메라 화면의 왼쪽 일반 TPS에 적합하지만, 카메라가 캐릭터 뒤로 즉시 회전하면 이동 기준도 계속 변할 수 있습니다.
캐릭터 기준 캐릭터가 바라보는 방향의 왼쪽 이번 요청에 해당합니다. 단, 입력 중 매 프레임 기준을 갱신하면 원형 회전 문제가 생깁니다.

4. 해결 원리

가장 중요한 원리는 조이스틱을 누르고 있는 동안 캐릭터 기준을 계속 갱신하지 않는 것입니다.

다음처럼 매 프레임 현재 캐릭터 방향을 직접 사용하면 안 됩니다.
(transform.right * input.x) + (transform.forward * input.y)
왼쪽 입력 → 캐릭터 왼쪽 회전 → 새로운 왼쪽 방향 재계산 → 다시 왼쪽 회전의 순환이 생길 수 있습니다.

5. BaseMoveController에서 필요한 수정

공통 이동·점프·중력 로직은 BaseMoveController에 그대로 두고, 조이스틱 전용 방향 계산만 자식 클래스에서 재정의합니다. 

// 변경 1: 자식 클래스에서 강제로 true로 설정할 수 있도록 protected로 변경
[SerializeField] protected bool m_faceMoveDirection = true;

// 변경 2: 자식 클래스에서 이동 방향 계산을 재정의할 수 있도록 virtual로 변경
protected virtual Vector3 BuildMoveWorld(
    Vector2 moveInput,
    Vector3 camForward,
    Vector3 camRight)
{
    return (camRight * moveInput.x) + (camForward * moveInput.y);
}

// 변경 3: JoystickMoveController에서 추가 초기화가 가능하도록 virtual로 변경
public virtual void StopMove()
{
    // 기존 StopMove 내용은 그대로 유지합니다.
}

protected

자식 클래스인 JoystickMoveController가 m_faceMoveDirection에 접근할 수 있게 합니다.

virtual

Base 구현을 유지하면서 자식 클래스가 특정 메서드만 다른 방식으로 구현할 수 있게 합니다.

override

JoystickMoveController가 실제 캐릭터 기준 이동 계산과 추가 초기화를 담당합니다.

BuildMoveWorld()가 private 상태이면 자식 클래스에서 override할 수 없습니다. 반드시 protected virtual로 변경해야 합니다.

6. 최종 JoystickMoveController.cs

아래 코드는 입력을 시작한 순간의 캐릭터 forward/right를 저장하고, 조이스틱을 놓을 때까지 그 기준을 유지하는 최종 권장 구현입니다. 

using UnityEngine;

/// <summary>
/// BaseMoveController를 상속받는 조이스틱 전용 이동 컨트롤러입니다.
///
/// 핵심 동작
/// 1. 조이스틱 입력을 시작한 순간의 캐릭터 방향을 기준으로 저장합니다.
/// 2. 왼쪽/오른쪽/앞/뒤 입력을 저장된 캐릭터 기준으로 계산합니다.
/// 3. 캐릭터는 계산된 이동 방향을 바라보면서 이동합니다.
/// 4. Cinemachine 카메라는 회전한 캐릭터의 뒤를 따라갑니다.
/// 5. 조이스틱을 놓으면 기준 방향을 초기화합니다.
/// </summary>
public class JoystickMoveController : BaseMoveController
{
    [Header("Joystick Move")]

    [Tooltip(
        "이 값보다 작은 조이스틱 입력은 무시합니다.\n" +
        "조이스틱을 놓았는데 캐릭터가 조금씩 움직이는 현상을 방지합니다."
    )]
    [SerializeField, Range(0f, 0.5f)]
    private float m_moveDeadZone = 0.1f;

    // 조이스틱 입력 시작 시점의 캐릭터 방향을 저장했는지 나타냅니다.
    private bool m_hasMoveReference;

    // 조이스틱 입력 시작 시점의 캐릭터 앞 방향입니다.
    private Vector3 m_referenceForward = Vector3.forward;

    // 조이스틱 입력 시작 시점의 캐릭터 오른쪽 방향입니다.
    private Vector3 m_referenceRight = Vector3.right;

    protected override void Awake()
    {
        // BaseMoveController의 초기화를 먼저 실행합니다.
        base.Awake();

        // 캐릭터가 반드시 실제 이동 방향을 바라보게 합니다.
        m_faceMoveDirection = true;

        ResetMoveReference();
    }

    private void OnDisable()
    {
        // 오브젝트가 비활성화될 때 이전 입력 기준이 남지 않게 합니다.
        ResetMoveReference();
    }

#if UNITY_EDITOR
    private void OnValidate()
    {
        // Inspector에서 실수로 꺼도 다시 켜진 상태를 유지합니다.
        m_faceMoveDirection = true;

        // Dead Zone 값이 올바른 범위를 벗어나지 않게 합니다.
        m_moveDeadZone = Mathf.Clamp(m_moveDeadZone, 0f, 0.5f);
    }
#endif

    /// <summary>
    /// 조이스틱 입력을 캐릭터 기준 월드 이동 방향으로 변환합니다.
    /// </summary>
    protected override Vector3 BuildMoveWorld(
        Vector2 moveInput,
        Vector3 camForward,
        Vector3 camRight)
    {
        // 아날로그 조이스틱 입력 강도를 0~1 범위로 제한합니다.
        float inputMagnitude = Mathf.Clamp01(moveInput.magnitude);

        // Dead Zone보다 작으면 조이스틱을 놓은 것으로 판단합니다.
        if (inputMagnitude <= m_moveDeadZone)
        {
            ResetMoveReference();
            return Vector3.zero;
        }

        // 새로운 조이스틱 입력이 시작된 순간에만
        // 현재 캐릭터의 앞/오른쪽 방향을 저장합니다.
        if (m_hasMoveReference == false)
        {
            // 캐릭터 앞 방향을 바닥 평면에 투영합니다.
            m_referenceForward =
                Vector3.ProjectOnPlane(transform.forward, Vector3.up);

            // 비정상적으로 방향이 너무 작다면 월드 앞 방향을 사용합니다.
            if (m_referenceForward.sqrMagnitude < 0.0001f)
            {
                m_referenceForward = Vector3.forward;
            }
            else
            {
                m_referenceForward.Normalize();
            }

            // 저장된 앞 방향을 기준으로 정확한 오른쪽 방향을 계산합니다.
            m_referenceRight =
                Vector3.Cross(Vector3.up, m_referenceForward).normalized;

            m_hasMoveReference = true;
        }

        // x 입력: 저장된 캐릭터 기준 왼쪽/오른쪽
        // y 입력: 저장된 캐릭터 기준 앞/뒤
        Vector3 moveWorld =
            (m_referenceRight * moveInput.x) +
            (m_referenceForward * moveInput.y);

        moveWorld.y = 0f;

        if (moveWorld.sqrMagnitude < 0.0001f)
        {
            return Vector3.zero;
        }

        // 방향은 정규화하고 조이스틱 입력 강도는 다시 적용합니다.
        return moveWorld.normalized * inputMagnitude;
    }

    public override void StopMove()
    {
        // BaseMoveController의 입력/상태 초기화를 실행합니다.
        base.StopMove();

        // 조이스틱 전용 방향 기준도 함께 초기화합니다.
        ResetMoveReference();
    }

    /// <summary>
    /// 조이스틱 입력 시작 시 저장한 캐릭터 기준을 초기화합니다.
    /// </summary>
    private void ResetMoveReference()
    {
        m_hasMoveReference = false;
        m_referenceForward = Vector3.forward;
        m_referenceRight = Vector3.right;
    }
}
중요: 이 컴포넌트는 BaseMoveController를 상속하므로 동일한 플레이어에 BaseMoveController 컴포넌트를 별도로 함께 붙이지 않습니다.

11. 자주 발생하는 문제와 해결 방법

왼쪽은 여전히 항상 -X, 오른쪽은 항상 +X로 이동합니다.

JoystickMoveController의 BuildMoveWorld() override가 실제로 호출되는지 확인합니다.

Base의 BuildMoveWorld()가 반드시 protected virtual이어야 합니다.

플레이어에 기존 BaseMoveController가 동시에 붙어 있지 않은지 확인합니다.

캐릭터가 한 방향으로 계속 빙글빙글 돕니다.

매 프레임 transform.right와 transform.forward를 직접 사용하고 있을 가능성이 큽니다.

입력 시작 순간에 저장한 m_referenceForward, m_referenceRight를 사용해야 합니다.

캐릭터는 잘 회전하지만 카메라가 뒤로 오지 않습니다.

CameraTarget이 플레이어 자식인지 확인합니다.

CinemachineCamera의 Tracking Target이 CameraTarget인지 확인합니다.

Follow Binding Mode를 Lock To Target With World Up으로 설정합니다.

Follow Offset Z가 음수인지 확인합니다. 예: -4

카메라가 너무 늦게 따라오거나 옆으로 밀립니다.

Position Damping X와 Z를 0에 가깝게 낮춥니다.

완전히 즉시 따라오게 하려면 X/Y/Z를 모두 0으로 테스트합니다.

조이스틱을 놓아도 캐릭터가 조금씩 움직입니다.

Move Dead Zone을 0.1에서 0.15 정도로 높입니다.

입력 시스템 또는 조이스틱 UI가 정말 0을 전달하는지도 확인합니다.

Face Move Direction을 끄면 해결될 것 같지만 정면만 봅니다.

이번 구조에서는 반드시 켜야 합니다.

끄면 Base의 기존 회전 로직이 이동 방향 대신 카메라 정면을 바라보도록 처리합니다.

12. 최종 테스트 체크리스트

  • 플레이어에는 JoystickMoveController만 붙어 있다.
  • Face Move Direction이 체크되어 있다.
  • Camera Transform에 Main Camera가 연결되어 있다.
  • CameraTarget이 플레이어의 자식이다.
  • Cinemachine Tracking Target은 CameraTarget이다.
  • Binding Mode는 Lock To Target With World Up이다.
  • 왼쪽 입력이 현재 캐릭터 방향의 왼쪽으로 작동한다.
  • 오른쪽 입력이 현재 캐릭터 방향의 오른쪽으로 작동한다.
  • 뒤 입력 시 캐릭터가 돌아선 뒤 이동한다.
  • 캐릭터 회전 후 카메라가 새 방향의 뒤쪽으로 이동한다.
  • 조이스틱을 놓았다가 다시 누르면 새로운 캐릭터 방향이 기준이 된다.
  • 캐릭터가 원을 그리며 계속 회전하지 않는다.

한 문장으로 정리

입력 시작 순간의 캐릭터 Forward/Right를 저장하고, 그 기준으로 이동 방향을 계산하며, Face Move Direction으로 캐릭터를 회전시키고, Cinemachine Follow가 회전한 캐릭터의 뒤를 따라가게 합니다.
