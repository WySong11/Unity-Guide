Unity-Technologies/skills를 실제 Unity 프로젝트에서 쉽고 안전하게 활용하기 위한 정리본

5. Skill별 실제 활용 예시

ui / ui-ugui

ui는 Router 역할을 합니다. Canvas/RectTransform이 보이면 ui-ugui, UIDocument/UXML이면 ui-uitk, OnGUI 기반이면 ui-imgui로 연결합니다.

장점: 기존 Canvas를 통째로 다시 만드는 대신, Hierarchy와 LayoutGroup을 먼저 확인한 뒤 문제가 있는 부분만 최소 수정하도록 유도합니다.

physics-3d-collision

단순히 Collider만 보지 않고 Rigidbody, Kinematic, Layer Collision Matrix, CharacterController 여부까지 함께 검사합니다.

// CharacterController 사용 시
void OnControllerColliderHit(ControllerColliderHit hit)
{
}

initialize-ai-navigation

NavMeshSurface ↓ Bake 상태 ↓ NavMeshAgent ↓ NavMeshObstacle ↓ NavMeshLink / Modifier ↓ AI Movement Script

urp-postprocessing

URP 활성화? ↓ HDR? ↓ Camera Post Processing? ↓ Volume Layer Mask? ↓ Global Volume? ↓ Volume Profile? ↓ Override State? ↓ Bloom / ColorAdjustments 활성화?
overrideState = true;

optimize-text-mesh-pro

Main Font ↓ Fallback CJK Font ↓ Fallback Symbol Font

한글/일본어/중국어 프로젝트에서 Static/Dynamic Font, Atlas, Fallback, AutoSize까지 함께 점검하는 데 유용합니다.

7. Pipeline / MCP 연결

Skill은 지식이고, 실제 Unity Editor를 만지려면 Pipeline/MCP가 필요합니다.

Pipeline 설치 
unity pipeline install
Pipeline 상태 확인 
unity pipeline list
Codex용 Unity CLI Skill 설치 
unity skill install codex --local
Codex에 MCP 연결 
unity mcp configure codex --local
Unity Editor 실행 후 연결 확인 
unity status
Editor가 제공하는 명령 확인 
unity command
Pipeline이 설치되어 있어도 Unity Editor가 실행 중이 아니면 실제 Scene/GameObject 조작은 할 수 없습니다.

eval이 제공되는 경우 Unity Editor 안에서 C#을 직접 실행할 수도 있습니다.

new UnityEngine.GameObject("TestObject");

8. Codex 요청 예시

UI 생성

현재 Unity Editor에 연결해서
현재 Scene과 Canvas 구조를 먼저 분석해줘.

uGUI를 사용하고 있는지 확인하고,
기존 UI 구조와 네이밍 규칙을 유지해.

Canvas 아래에 LoginPanel을 만들어줘.

LoginPanel에는
- ID TMP_InputField
- Password TMP_InputField
- Login Button
- Message TMP_Text

를 배치해.

Canvas에 직접 생성하고
Prefab으로 새로 만들지는 마.

기존 UI는 삭제하거나 재생성하지 말고
필요한 부분만 추가해.

작업 후 실제 Hierarchy를 다시 확인해서
생성 결과를 알려줘.

NavMesh 설정

현재 Scene의 Navigation 설정을 먼저 분석해줘.

NavMeshSurface,
NavMeshAgent,
NavMeshObstacle이 있는지 확인해.

Monster가 Player를 추적할 수 있도록
AI Navigation을 구성해줘.

기존 Navigation 설정이 있다면
새로 만들지 말고 재사용해.

필요한 부분만 추가한 다음
Agent Type과 Bake 상태까지 확인해줘.

Global Volume 점검

현재 URP Global Volume이
정상적으로 작동하는지 검사해줘.

다음을 순서대로 확인해.
1. URP 활성화
2. HDR
3. Camera Post Processing
4. Volume Layer Mask
5. Global Volume
6. Volume Profile
7. overrideState
8. Bloom
9. ColorAdjustments

Pipeline의 eval을 사용할 수 있다면
Unity Editor 내부에서 직접 검사해.

문제가 있으면 전체 Volume을 다시 만들지 말고
잘못된 설정만 수정해.

Multiplayer 구조 설계

Unity Multiplayer Services를 이용해서
4명이 참여하는 방 시스템을 만들어줘.

흐름은

→ Login
→ Lobby
→ Create Room / Join Room
→ Game

으로 사용하려고 해.

현재 프로젝트와 설치된 패키지를 먼저 분석해서
필요한 Multiplayer 구조를 설계해줘.

최신 Multiplayer Sessions 방식으로 구성하고
불필요한 서비스를 따로 추가하지 마.

10. 추천 작업 방식

Skill이 있다고 해서 "게임 전체를 한 번에 만들어줘"가 가장 좋은 사용법은 아닙니다. Unity 작업은 작은 단위로 나누고 매 단계 검증하는 것이 훨씬 안정적입니다.
1단계: 현재 프로젝트 분석 ↓ 2단계: 한 기능만 구현 ↓ 3단계: Unity Editor에서 실제 검증 ↓ 4단계: 문제 수정 ↓ 5단계: 다음 기능 진행

예:

1단계:
현재 프로젝트와 설치 패키지를 분석해줘.
코드는 수정하지 마.

2단계:
로그인 구조만 구현해줘.
작업 후 테스트해.

3단계:
Lobby UI만 만들어줘.

4단계:
Create Room 기능을 연결해줘.
